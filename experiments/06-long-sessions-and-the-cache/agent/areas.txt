Where things are (three areas):
- flutter: the app's Dart code is under lib/ and its tests under test/. Run test files with `flutter test --no-pub test/<name>_test.dart` (several files in one command is fine). The whole Flutter suite takes more than ten minutes: run the files related to what you change, not all of them.
- functions: the Cloud Functions (Node 20) are under lib/internal/firebase/functions/ and their Jest tests under lib/internal/firebase/functions/tests/. They need the local emulators, which take about a minute to start. Run files the way the task's own command does: cd lib/internal/firebase && FIREBASE_RULES_TEST_PROJECT_ID=app-test firebase emulators:exec --project app-test --only firestore,auth,storage "cd functions && NODE_OPTIONS=--experimental-vm-modules npx jest --runTestsByPath tests/<name>.test.js --runInBand --forceExit --watchman=false"
- rules: the security rules are lib/internal/firebase/firestore.rules and lib/internal/firebase/storage.rules. Their tests are the rules test files in the same Jest folder and run the same way as the functions tests.
Only one `firebase emulators:exec` can run at a time (fixed ports). A single command is cut after ten minutes.
